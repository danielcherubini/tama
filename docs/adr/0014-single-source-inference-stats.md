# Single-source inference stats: the tamad's /metrics scrape is the only writer, per-response extraction is retired

ADR-0012 fixed the *spec-decode* telemetry boundary (the tamad scrapes, the proxy never reads backend internals), but left the rest of the inference stats — `tps`, `prompt_tps`, `cache_hit_pct` — coming from the proxy's per-response extraction. That path was one request's *instantaneous* rate, maintained two staleness clocks (30s per-response gate vs 60s tamad blanking), made vLLM's `prompt_tps` depend on a user flag (`--enable-prompt-tokens-details`), and forced the per-response whole-entry replacement to carry the tamad-merged spec fields across to avoid clobbering them (plus a borrow-guard against a self-deadlock). We decided: **the tamad's 10s `/metrics` scrape becomes the sole source of ALL inference stats** (`tps`, `prompt_tps`, `cache_hit_pct`, `spec_accept_pct`, `spec_decoding_active`), and the per-response extraction is retired.

**Why:** vLLM's `/metrics` is on by default (no flag) and exposes the cumulative token counters a windowed diff needs — `generation_tokens_total`, `prompt_tokens_by_source{local_compute|local_cache_hit}` (the compute-vs-cache split, added 2026), and the three spec counters — while llama.cpp ≥ b7191 exposes the same shape (`tokens_predicted_total`, `prompt_tokens_total` with cache hits excluded, `prompt_tokens_cached_total`, and the same three spec counters since 2026-08-05) behind `--metrics`, which we now inject as a managed default. A 10s windowed server-level average is the more honest "backend tok/s": vLLM's per-response `tokens_per_second` is `num_gen / (last − scheduled)` and *includes the prefill phase*, and a single writer kills the two-clocks/two-writers tangle.

**Trade-off accepted:** a windowed rate dips toward 0 between bursts (a per-request value never goes to 0 mid-request), the display blanks 30s after the last traffic (the single clock; the spec fields previously blanked at 60s), `spec_decoding_active` un-sticks after 30s idle (it was a sticky OR), and llama.cpp backends without `--metrics` show no inference stats at all (no per-response fallback).

**Considered Options:**
- *Scrape primary, per-response as a silent fallback when the scrape is unavailable* — rejected: it keeps the two-writers tangle and requires "which wins" arbitration (freshness comparison, a second timestamp); the consistency goal was the point.
- *Per-response primary, scrape as fallback* — rejected: the per-request instantaneous value is the less honest number (includes prefill for vLLM), and the `--enable-prompt-tokens-details` dependency stays.
- *Standardise on llama.cpp's seconds counters (`tokens_predicted_seconds_total`) for a true busy-time rate* — rejected: that is a *different quantity* (processing speed while busy) than the windowed engine throughput; mixing engines on different quantities makes cross-engine numbers incomparable. Both engines use `Δtokens / Δt` (measured elapsed between scrapes).

**Consequences:**
- Wire: three new `optional double` fields on `ProcessInfo` (12-14) — explicit presence, so `0.0` (idle window) is distinguishable from "no observation"; old tamads omit them gracefully.
- Tamad: `vllm_metrics.rs` → `engine_metrics.rs` — the parser generalises to `vllm:` **and** `llamacpp:` prefixes (body-driven `engine_kind` detection: Vllm | Llamacpp | None), the per-window observation adds `tps`/`prompt_tps`/`cache_hit_pct` (disjoint-set cache semantics identical to the retired `cache_n/prompt_n`), and `STALE_MS` tightens 60s → 30s (the single staleness clock). Scrape-loop constraints unchanged (10s throttle, 2s timeout, 3s preflighted budget, whole-body fetch).
- llama.cpp: `--metrics` injected as a managed default (new `llama_cpp_args.rs` mirroring the vLLM managed-flags pattern); the tamad already probes every backend's `/metrics` every 10s (501 no-op today), so enabling it just turns a no-op into a payload.
- Proxy: the merge overwrites all five inference fields unconditionally **including `None`** (safe because the row is itself 30s-gated — the old "skip stale defaults" invariant is inverted, and there is no longer a second writer to protect), stamps `last_updated_ms` **only when `tps` is `Some`** (preserves "most recently active backend wins" in the aggregate), and the 30s `BUCKET_MS` gate degrades to a redundant backstop. `extract_inference_stats` + both extractors + call sites + `record_inference_stats` are deleted.
- Degradation (all graceful, body-driven): vLLM pre-2026 (no `by_source`) → `prompt_tps`/`cache_hit_pct` `None` (no raw-counter fallback — cache hits would inflate it); older llama.cpp → spec fields `None`; pre-b7191 llama.cpp → all `None` (the parser safely rejects the old JSON-escaped exposition).
